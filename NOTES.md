## Phase 1–2 (2026-10-12)

- **N1 Legacy is vendored, not a submodule.**
  - `legacy/` is a plain copy of `spring-petclinic/spring-framework-petclinic` at commit `cf392920cdbe9cd07689f1f4b603271940bac957` (2026-10-05), without its `.git`. Its Apache 2.0 `LICENSE.txt` is kept.
  - Why: a migration works against a frozen snapshot. The RAG indexer and agents need plain files. A submodule would make cloning and indexing clumsier for no benefit, since upstream changes are irrelevant mid-migration.
- **N2 Docker files live outside `legacy/`** (`docker/legacy.Dockerfile`, root `docker-compose.yml`), so the vendored code stays identical to upstream.
- **N3 Tomcat 11, not `mvn jetty:run-war`.**
  - Upstream's Jetty plugin is 11.x (Servlet 5), but Spring Framework 7 needs Servlet 6.1.
  - The image builds the WAR with Maven on Temurin 17 and deploys it as `ROOT.war` on `tomcat:11.0-jdk17-temurin`, so URLs sit at `/`.
- **N4 Legacy DB is H2 in memory**, reseeded on every start. `docker compose restart legacy` gives a clean slate.
- **N5 Playwright on WSL needed system libraries** (`libnspr4` and others).
  - `sudo npx ...` failed because nvm's Node is not on sudo's PATH, and the `!` prompt prefix has no TTY for the password.
  - Fix, in a normal terminal: `sudo ~/.nvm/versions/node/v24.19.0/bin/node node_modules/.bin/playwright install-deps chromium`.
- **N6 Selector contract** (top of `tests/characterization/support/helpers.ts`).
  - Tests find fields by HTTP `name`, buttons/links/headings by visible text, and errors by "innermost element wrapping the field".
  - Never by legacy CSS classes or JSP structure. Legacy labels have no `for=`, so `getByLabel` was not an option.
- **N7 Test isolation.**
  - Each test creates its own owner with a fixed-length random last name (search is a prefix match, so no generated name may be a prefix of another).
  - Seed data is only read.
  - Verified: 3 consecutive runs on a dirty DB, 198/198 passing.
- **N8 Correction: the empty-telephone message is NOT deterministic.**
  - I first recorded "always the digits message" from 4 samples, and one subagent repeated it. 12 identical requests then gave 5× `must not be empty` and 7× `numeric value out of bounds…`.
  - Cause: Hibernate Validator returns violations as an unordered set, and the JSP shows the first.
  - The test accepts either. Modern always shows `must not be empty` (SPEC D9).
- **N9 flatpickr rewrites date inputs.**
  - The server renders `2010/09/07`, but the date widget reformats the value to `2010-09-07` on page load. Legacy also accepts ISO dates, so submitting an unchanged form works.
  - Tests assert what the browser shows (`yyyy-MM-dd`) and that unchanged submits succeed.
  - The views subagent flagged this as a "probable bug". The suite showed it is not one.
- **N10 Null visit date crash needs two visits.**
  - A blank visit date saves NULL. The owner page 500s only once that pet has 2+ visits, because Java's sort skips lists shorter than 2.
  - My first `@legacy-bug` test assumed one visit was enough and failed. The domain subagent had predicted the nuance.
- **N11 Search is case-insensitive only because H2's column type is `VARCHAR_IGNORECASE`.** The JPQL is a plain `LIKE`. Postgres needs `ILIKE` to match.
- **N12 Legacy's own `db/postgresql/data.sql` differs from the H2 seed** (other birth and visit dates, reversed visit order). Modern seeds from the H2 values.
- **N13 `@legacy-bug` tests are excluded by default** (`grepInvert` in `playwright.config.ts`; run them with `INCLUDE_LEGACY_BUGS=1`). They document defects without forcing the rewrite to reproduce crashes. Each fix is listed in SPEC §8.
- **N14 Modern is tested on one origin (port 3000), not the Vite dev server.** Page URLs must return 404/400 where legacy does, and Vite answers everything with 200. `PROMPT.md` was updated from 5173 to 3000.
- **N15 All legacy defects (SPEC §8, D1–D10) are fixed in modern, not reproduced.** Decided 2026-10-12. Each one gets a write-up in `FINDINGS.md` after the migration (fix_plan task 23).
- **N16 License.** MIT for this project's own code (`LICENSE`); `legacy/` stays Apache 2.0.
- **N17 Postgres image is `pgvector/pgvector:pg17`.** It is plain Postgres 17 plus the vector extension, so Phase 4 (RAG) can reuse the same server. Host port 5433 (a local Postgres holds 5432).
- **N18 Ralph sandbox design** (`.devcontainer/`, adapted from Anthropic's reference dev container).
  - Docker Compose overlay: the agent's container joins the network with `legacy` and `db`, and reaches them by service name.
  - No Docker socket. Mounting it would give the agent root-equivalent control of the host.
  - Default-deny iptables firewall. Allowed: the Anthropic API, the npm registry, Claude login and telemetry domains, and the compose subnet. GitHub is deliberately blocked (the reference allows it), so the loop can commit but not push.
  - Verified 2026-10-12: example.com and github.com are blocked; npm, `legacy:8080` and Postgres are reachable; `sudo` is limited to the firewall script; 60/60 characterization tests pass from inside the container.
- **N19 Gotchas hit while building the sandbox.**
  - Relative paths in an overlay compose file resolve from the *first* compose file's directory (the repo root), not the overlay's.
  - Debian login shells reset PATH from `/etc/profile`, which hid the npm-global `claude` binary. Fixed with `/etc/profile.d/npm-global.sh`.
- **N20 GitHub push uses HTTPS with `gh` as the credential helper** (repo-local git config). SSH failed with "Permission denied (publickey)": the host key is not registered with GitHub, or needs a passphrase. The git identity is also set in repo-local config, so commits made inside the container use the same author.
- **N21 The agent never holds GitHub credentials** (decided 2026-10-12).
  - Goal: hands-off merging. Tried first: give the agent a bot token inside the sandbox. Claude Code's own safety check blocked writing that credential setup.
  - Chosen instead: split roles. The agent (sandbox) only edits and commits. The host orchestrator (`ralph.sh`, the human's `gh` login) pushes, opens a PR into `migration` with auto-merge, waits for CI, and feeds failures back through `.ralph/ci-feedback.md`.
  - Same autonomy, smaller blast radius. The sandbox firewall keeps blocking GitHub.
- **N22 Threat model for the shared checkout.** The agent writes to the same working tree the host orchestrator runs git in. Mitigations:
  - The prompt is read from `origin/migration`, not the working tree.
  - `ralph.sh` runs as one function, so bash has parsed it all before any edit could land.
  - Host git runs with `core.hooksPath=/dev/null` and `core.fsmonitor=false`.
  - `.git/config` and `.git/hooks` are mounted read-only in the container. Verified: config and hook writes fail, commits work.
  - The loop stops if protected paths change or the agent leaves the branch or uncommitted work.
- **N23 Merge gate** (`.github/workflows/ci.yml`). Every PR runs:
  - the characterization suite against legacy, including `@legacy-bug` tests;
  - build, lint and unit tests for modern;
  - the **ratchet**: tests listed in `modern/ratchet.txt` must pass against modern, and lines may never be removed.

  Agent branches (`ralph/*`) may not touch tests, CI, sandbox or prompt files. The path guard keys on the branch prefix. It guards against mistakes, not a determined adversary. The real boundary is that the agent cannot push at all.
- **N24 Integration-branch model.**
  - Agent PRs auto-merge into `migration` (squash, linear history, CI required).
  - When a `fix_plan.md` section completes, the orchestrator opens or updates a `migration` → `main` milestone PR. The human reviews and merges it with a merge commit.
  - `main` requires CI but no approval: a solo maintainer cannot approve their own PR, and only humans can act on GitHub anyway.

  - npm and Playwright browser caching.
  - Postgres as a service container.
  - `legacy/` and `docker/` became protected paths, which is what makes skipping the legacy suite on agent PRs safe.

- **N38 Orchestrator v2: conflicts are part of the loop, not a failure.** My parallel PRs (#9, #10) left the loop's PR #11 conflicting in `NOTES.md`. v1 saw "no CI checks" (GitHub runs no CI on a conflicting PR), called it a CI failure, and gave the agent an empty log to "fix". v2:

  - Re-checks a resumed PR without running the agent when there is no feedback.

- **N44 Task 4: reset runs through `pg`, not `psql`.** `db:reset` builds and runs `dist/db-reset.js`, which loads `db/schema.sql` and `db/seed.sql` in one transaction, so CI needs no Postgres client binary. The seed inserts explicit ids (the legacy H2 file uses `default`) so ids never depend on sequence state, then `setval`s each sequence to `max(id)`. Vitest now runs test files serially (`fileParallelism: false`) because integration tests share one database.
- **N45 Task 5: DATE columns stay strings.** node-postgres parses `DATE` into a JS `Date` at local midnight, so a non-UTC server can shift `2010-09-07` by a day. The pool uses its own `TypeOverrides` (not the global `pg.types`) to return `DATE` as the raw `yyyy-MM-dd` text, matching legacy's `LocalDate`; `PetRow.birth_date` and `VisitRow.visit_date` are `string | null`.
- **N46 Retrieval eval (Phase 6).** Measured on 22 development and 12 held-out questions (`rag/README.md` "Eval").
  - Postgres `ts_rank` has no IDF, so keyword search, and a hybrid built on it, did worse than vectors alone. BM25 fixed that.
  - The 2.5x larger `mxbai-embed-large` lost to `nomic-embed-text`.
  - Hybrid (BM25 + nomic) won the development set: 21/22 in the top 5 vs 19. The held-out set, written before its results existed, was mixed: better hit@1 and MRR, one fewer top-5 hit. So hybrid ships as `RAG_STRATEGY=hybrid` with the default unchanged, instead of switching production behavior on a within-noise difference. This is the dev/held-out discipline: decide on one set, confirm on fresh data.
- **N47 Parity report.** `node scripts/parity-report.mjs` writes `docs/PARITY.md`: characterization tests per spec file, all passing on legacy, and on modern the ones listed in `modern/ratchet.txt`. Both columns are CI-verified, so the report claims nothing CI does not enforce.
- **N48 Task 6: dates are a plain `{ year, month, day }`, and year 0 is rejected.** Legacy's strict `uuuu` parsing accepts `0000/01/01`, but Postgres has no year 0 and would fail the insert, so modern returns `invalid date` instead of a 500. Years are exactly 4 digits.
- **N49 Task 7: telephone parity goes beyond ASCII.** Probing the running legacy app showed that `@Digits` (`new BigDecimal(String)`) accepts any BMP Unicode decimal digit (`١٢٣`, `０１`, `1e٠٩`), counts precision without leading zeros (`00000000000001` passes, `0E9` passes, `0E10` fails) and rejects any fraction scale (`1.0`, `10E-1`), while `1.` passes. It rejects supplementary-plane digits like `𝟏` because Java reads UTF-16 chars. `isValidTelephone` reproduces each of these cases. The probes left 12 `zzprobe` owners in the sandbox's legacy DB, which no test searches for.
- **N50 Task 8: Java's case-insensitive order is not `localeCompare`, and not quite lowercasing.** `String.CASE_INSENSITIVE_ORDER` maps each code point through `toUpperCase` then `toLowerCase` and compares numbers, so `é` sorts after `z` and dotless `ı` equals `i`; `compareCaseInsensitive` mirrors it (pets, specialties). The duplicate-pet check is different again: `Owner.getPet` lowercases whole strings, so `ı` vs `i` is not a duplicate there. `validatePet` also rejects an unknown type name with `invalid value` (D5), on edit too, and visit sorting puts any legacy NULL date last instead of throwing (D1).
- **N51 Code review of milestone PR #20** (`/code-review`, 10 findings). Each was verified before fixing; 9 were in my code and 1 in the agent's.
  - Search CLI dropped the question when `-k` was omitted, the documented usage. My manual tests always passed `-k`.
  - MCP server's entry check compared a URL to a raw path, so it would silently not start under a path with a space.
  - `ralph.sh`:
    - Failures inside `$(...)` did not stop functions, and output could leak into variables. Fixed with `shopt -s inherit_errexit`; a minimal repro confirmed it.
    - Conflict file names were lost in a subshell.
    - Used feedback was never deleted, so a resume would redo it.
  - Keyword search lowercased before splitting camelCase. Re-running the eval left every number unchanged, because no eval question contains an identifier. Still a real bug for agent queries.
  - Hybrid mode rebuilt the BM25 index on every call. It is now cached per process.
  - Parity script duplicated the ratchet's test-id logic and presented the legacy column as measured. They now share `.github/scripts/test-ids.mjs`, and the columns say "CI requires".
  - `rag/` and `mcp/` had no CI coverage. They are now protected paths for the agent; a CI job needs the `workflow` scope and is a follow-up.
  - The agent's date parser rejects signed 5+-digit years that legacy accepts. Recorded as accepted divergence D11 rather than replicated.
- **N52 Task 9: legacy ids are not just digits.** Spring binds `@PathVariable int` via `NumberUtils.parseNumber`, which strips every Java whitespace char (even inside: `1 2` is 12) and decodes hex: probing legacy, `/owners/+1`, `0x1`, `%231`, `01`, `١` and `0xＡ` all resolve, while `1.0`, `0x`, `+0x1`, a no-break space and 2147483648 give 400. `parseLegacyId` mirrors this for the API (and later page routes). The read API returns nullable text columns as `''`, as JSP renders them, and sorts pets, visits, vets and specialties in JS so Postgres's `en_US` collation never decides an order legacy decided in Java.

- **N56 Task 10: the vets bodies are built as strings, not by a serializer.** Jackson orders bean properties alphabetically (`firstName, id, lastName, new, nrOfSpecialties`) and JAXB emits one line with repeated `<specialties>`, so `vetsJson`/`vetsXml` write that exact shape; the unit test compares against bodies captured from the running legacy app, including `Content-Type: application/...;charset=UTF-8`. Not replicated: legacy answers 406 when `Accept` excludes the produced type. Also, a stale `node dist/server.js` from an earlier iteration was still holding port 3000, so a freshly started server failed to bind and the suite silently ran against old code; check the server pid before trusting a ratchet run.
- **N57 Task 11: validation runs before the id is looked up.** Legacy's `@Valid` binds and validates before `processUpdateOwnerForm` runs, and its `UPDATE ... WHERE id=:id` silently changes 0 rows for an unknown id (the redirect then shows the error page). So `PUT /api/owners/999` with a bad body is 422, and with a valid one 404. Non-string body fields count as missing (`must not be empty`), and a body `id` is ignored, as legacy's binder disallows `id`.
- **N58 Task 12: the owner is resolved before the pet is validated, unlike owner PUT.** `PetController.findOwner` is a `@ModelAttribute`, so it runs (and throws for an unknown owner) before `@Valid Pet` binds: `POST /api/owners/999/pets` with a bad body is 404, not 422. An unknown or foreign pet under a real owner is still checked after validation, via `UPDATE ... WHERE id = $petId AND owner_id = $ownerId` (D7 fix: a pet can never move owners). Legacy's edit would NPE in `createPetParameterSource` with no type; modern keeps the pet's current type instead.
- **N59 Task 13: the visit route checks the pet, never the owner.** `VisitController.loadPetWithVisit` is a `@ModelAttribute` on `petId` alone, so an unknown pet is 404 before the body is validated, while `{ownerId}` is only used for the redirect: `POST /api/owners/1/pets/7/visits` adds a visit to owner 6's pet (D8, kept for parity). The owner id must still parse, as on every other API route. Visits are insert-only, as `JdbcVisitRepositoryImpl.save` throws on update.
- **N60 Task 14: Fastify owns every page status, so the SPA has no catch-all route.** The page patterns mirror the legacy controllers, probed with curl: `/owners/abc/pets/1/visits/new` is **200** because `VisitController` maps `/owners/*/pets/{petId}/visits/new` and never binds the owner, while `/owners/1/`, `/vets/` and even `/index.html` are 404 in legacy, so `index.html` is only served through a page route. Ids use task 9's `parseLegacyId`, so `/owners/+1` is 200 and `/owners/%20` is 400, as in legacy. The copied `public/resources/` is excluded from Prettier to stay byte-identical to legacy.
- **N61 Task 15: the active menu item is a per-page prop, not derived from the URL.** Each legacy JSP passes `pageName` to `layout.tag`, and `exception.jsp` uses `error` even when reached via `/owners/999999`, so `Layout` takes `menu` explicitly. Two legacy quirks kept for parity: inactive items render `<li class="">`, and the Error item's glyph is `exclamation-triangle` without the `fa-` prefix, so legacy shows no icon there. The Bootstrap 5.3.8 bundle (legacy's `footer.tag`) is imported so the navbar toggler works on narrow screens. The navbar test waits on tasks 16–18. Careful: `pkill -f <pattern>` also kills the agent's own shell when the pattern appears in its command line.
- **N62 Task 16: the error page is client-rendered, so its 200 is just the page route's.** Legacy's `SimpleMappingExceptionResolver` renders `exception.jsp` with 200 and the `error` menu item active for any thrown exception; modern gets the same status for free because Fastify already answered `/owners/999999` with `index.html`, and `OwnerDetails` swaps in `ErrorPage` when `/api/owners/:id` is 404.
